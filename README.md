# SnowLuma Bridge

**多 QQ、多下游的自由控制台。**

统一管理多个 QQ 账号和服务连接，用可组合的算子编排下游的流程配置，再为每个会话选择「下游 + 配置文件」。面向喜欢折腾 AI 和聊天机器人的个人玩家，支持本地部署。

```text
多个 QQ → OneBot → 会话选择「下游 + 流程配置」
                              ↓
       算子 A                  算子 B                  算子 C …
  读取 / 处理 / 返回  →  调用 / 处理 / 再调用  →  处理 / 返回 / 结束
```

## 核心概念

| 对象 | 负责什么 | 示例 |
|---|---|---|
| QQ 账号 | 接收消息、从原账号回复 | 主号、测试号 |
| 下游连接 | 地址、协议、认证和服务状态 | dsh、酒馆、自建 HTTP |
| 操作 | 执行一个具体动作 | 读取数据、处理内容、调用服务、返回 QQ、结束流程 |
| 算子 | 按顺序组合一个或多个操作 | 提取变量后直接回复、调用接口后处理结果 |
| 流程配置 | 属于某个下游的一组有序算子 | 日常聊天、客服查询，可导入/导出 JSON |
| 会话管理 | 选择下游与对应流程配置、维护变量 | 私聊走 dsh 的日常聊天配置 |

算子没有固定的上游、中间、下游位置。每个算子都可包含处理和返回操作，服务调用和返回可以重复出现。返回可继续执行，也可结束流程。调用默认使用所属下游，也可显式选择其他已有连接进行串联。

原「会话配置」页面已移除，提示词、提取、变量赋值与文本规则直接保存在算子的处理操作中。会话只选择连接和流程配置。群聊按「账号 + 群 + 成员」隔离；全局默认组合和每个下游的默认流程配置分别保存。

## 已有能力与边界

- **多 QQ**：多条 OneBot v11 连接，按账号隔离会话，从原账号回复。
- **多下游**：dsh 插件 / headless、SillyTavern、同步 HTTP GET/POST；同类型可多个实例。
- **算子编排**：增删、复制、排序算子；算子内操作也可调整顺序。没有隐式调用或隐式回复。
- **内容处理**：提示词、前后追加、替换/删除/去除标记内容、正则或 JSON 数据提取、持久变量赋值。
- **调试**：模拟执行、按调用操作分别填写模拟回复、连续多轮预览、隔离的真实调用测试、逐算子与操作记录。
- **运行状态**：上游与下游状态、日志、SSE 状态推送、分段与图片表情。
- **上游连接**：读取 SnowLuma 已有 OneBot 端点后主动连接；诊断注入状态，不执行自动注入。

当前为有序串行编排，尚未提供条件分支、循环、并行、任意脚本和分布式调度。最多 32 个算子，每个算子 16 个操作，整个流程最多 128 个操作。HTTP 支持同步 GET/POST 和 JSON / 文本响应，尚不支持 SSE 或异步轮询。dsh 适配助手只生成连接参数与协议映射。

## 快速开始

需要 Node.js >= 22、pnpm >= 11、一个 QQ OneBot v11 协议端和一个可用下游。

```bash
git clone https://github.com/BRXYM/SillyTavern-QQ-Bridge.git
cd SillyTavern-QQ-Bridge
git checkout next
pnpm install
```

`next` 是完整前后端工程；`main` 保留历史版本。首次运行（PowerShell）：

```powershell
Copy-Item apps/server/config.example.json apps/server/config.json
pnpm dev
```

打开 <http://localhost:5178>：

1. 在 **上游连接** 中检测 SnowLuma，选择已读取的 QQ，点击「连接此 QQ」。QQ 须先在 SnowLuma 中手动注入，并启用 OneBot WebSocket 服务。控制台只读取已有端点，不修改 SnowLuma 文件；也可手动添加 OneBot 连接。
2. 在 **下游连接** 中添加或启用服务，填写地址、认证与协议映射。默认使用 dsh，也可连接酒馆或 HTTP 服务。
3. 在 **消息流程** 中新建配置，选择所属下游。通过添加、复制、前移和后移组织算子，点击算子编辑其中的操作。
4. 可以载入「先确认，再处理」示例：第一个算子先返回确认消息，第二个算子调用、处理并返回结果。先模拟执行，再按需真实调用测试。
5. 保存流程；在 **会话管理** 中选择下游和该下游的流程配置。也可设为下游默认或全局默认组合。
6. 在 **最近执行** 中展开每个算子和操作，查看输入输出、耗时、错误、变量变化及各次返回内容。触发和准入设置仍在系统设置中。

注入诊断优先读取 SnowLuma 的进程接口；Windows 可补充检查 QQ 主进程与 SnowLuma 注入管道。无法读取、需要 WebUI 登录或无法对应账号时，显示“未知”，不会把连接失败直接当作“未注入”。控制台不执行自动注入，也不修改自动注入开关。

### dsh

需要时安装 `npm install -g @deepseek-ai/dsh`。在下游连接中展开 dsh 实例，探测安装位置、设置 profile，并使用「一键安装插件」。源码位于 `apps/dsh-plugin`。详细操作见 [后端说明](apps/server/README.md)。

### SillyTavern

把 `apps/extension/` 复制到酒馆的 `public/scripts/extensions/third-party/SnowLuma-Bridge/`，重启酒馆，确认扩展连接 Bridge 的 WebSocket 端口（默认 9500），再启用酒馆下游。

### 自建 HTTP 服务

在下游连接中新增 HTTP 类型，配置 URL、method、headers、timeoutMs、response 和 requestBody。requestBody 属于接口协议映射，例如：

```json
{
  "message": "{{input.text}}",
  "system": "{{input.system}}",
  "session_id": "{{input.sessionKey}}"
}
```

前置提示词与文本处理在算子的处理操作中定义；认证使用请求头中的 `{{env.变量名}}` 引用。不要将真实密钥提交到仓库。

### 旧配置兼容

旧会话绑定与运行文件保留，尚未保存的新编辑定义不会改变原处理方式。编辑器会将原配置展开为算子，保存后参数直接属于流程，不再引用原会话配置。未改变连接时保留旧协议覆盖；旧上下文可通过调用操作中的兼容选项继续使用。历史 API 只为兼容旧版本保留，旧 `/profiles` 页面跳转到流程页。

## 算子、操作与数据

每个算子都有稳定 ID 和操作列表，按从左到右、从上到下的顺序执行。支持：

| 操作 | 效果 |
|---|---|
| 读取数据 | 将模板展开为当前文本，可读取原文、前面算子输出、历史或变量 |
| 处理内容 | 初始化变量 → 提取 → 同时赋值 → 文本规则 → 前后追加；可设置后续调用提示词 |
| 调用服务 | 向所选连接发出一次请求，服务回复成为当前文本 |
| 返回 QQ | 展开返回模板，从原账号发送；可继续或结束，不改变当前文本 |
| 结束流程 | 停止后续操作，不自动发送当前文本 |

例如一个算子可以包含 `返回“正在查询” → 调用接口 → 提取订单号 → 返回查询结果`，也可拆成多个算子。流程末尾没有返回操作时，不会自动发送服务结果。

| 引用 | 数据 |
|---|---|
| `{{text}}` / `{{system}}` | 当前文本 / 当前调用提示词 |
| `{{message.upstream}}` | 本轮 QQ 原文 |
| `{{message.downstream}}` | 本轮最近一次服务原始回复 |
| `{{extracted.nickname}}` | 当前算子已提取的值 |
| `{{operators.receive.extracted.nickname}}` | 本轮 receive 算子提取的值 |
| `{{operators.receive.output}}` | 本轮 receive 算子当前或最终输出 |
| `{{history.receive.extracted.nickname}}` | 本会话上次保存的 receive 提取值 |
| `{{history.receive.output}}` | 上次保存的 receive 输出，最多保留 4000 字 |
| `{{vars.nickname}}` | 当前会话的持久变量 |

未来才执行的数据本轮尚不存在，读取时给出诊断并按空文本处理；可改用上轮 history 或变量。其他软件的宏（如 `{{char}}`）保留原文，用户数据不会被递归解释。旧 `current.upstream/downstream`、`previous.upstream/downstream` 引用在迁移操作中继续兼容。

提取支持正则捕获组与 JSON 点路径，如 `data.name`、`items.0.name`。同一操作的提取先完成，变量赋值随后同时生效；赋值默认不以空值覆盖旧值。同一算子多次提取相同名称时以后一次为准。

变量和历史按完整会话 key 隔离，切换流程同名变量沿用。初始值仅在变量尚不存在时使用。最多 32 个变量，每值 4000 字；算子历史的输入输出各保留 4000 字，单会话状态最多 512000 字，全部状态文件最多 16 MiB。数据原子保存于 `apps/server/data/conversation-state.json`，重启保留且不提交 Git。

## 执行、检查点与测试

同一会话顺序执行，不同会话各自处理。**每次真实返回前保存此前状态，流程完成时再保存最终状态**。如果后续操作失败，已经发出的消息、已经完成的服务调用及已保存的检查点保留；尚未保存的变量不生效。不自动重试，以免重复调用或重复回复。

模拟执行不访问服务、不投递 QQ、不写真实变量，可沿用模拟状态进入下一轮。多个调用可按 `算子ID.操作ID` 分别提供模拟回复。真实调用测试会执行所有服务调用，使用独立测试会话并在结束后请求清理；返回操作仅展示，不投递 QQ，也不修改真实会话状态。外部服务可能产生正常调用费用或自身记录。

最近执行在内存保留 50 次，重启清空。逐算子和操作记录输入、输出、提示词、耗时、错误，以及各次返回和变量是否已保存；正文记录最多 4096 字。不采集连接认证和请求头，消息本身仍可能包含用户敏感内容。

新调用操作对「会话 + 流程 + 算子 ID + 操作 ID」生成稳定摘要，隔离下游上下文并避免工作目录名截断造成碰撞。排序不会改变 ID；删除重建会建立新上下文。流程文件只保存连接引用和算子参数，可从页面导入/导出；连接凭据仍由下游连接管理。[先确认再处理示例](examples/flows/ack-then-reply.json) 可直接导入，默认引用 `dsh`。

## 开发与部署

```bash
pnpm dev          # 前后端
pnpm dev:web      # 仅前端
pnpm dev:api      # 仅后端
pnpm build        # 构建前端
pnpm start        # 仅后端，不托管网页
pnpm test         # 自动化测试
pnpm typecheck    # 前后端类型检查
```

| 环境变量 | 默认值 | 用途 |
|---|---|---|
| WEB_PORT | 5178 | 开发控制台 |
| API_PORT | 9510 | HTTP API |
| EXT_PORT | 9500 | 下游插件 WebSocket |
| ONEBOT_URL / ONEBOT_TOKEN | 配置文件 | 覆盖第一个 QQ 账号连接 |
| ST_DATA_DIR | 自动探测 | 酒馆数据目录 |
| BRIDGE_OPEN | 关闭 | 设为 1，启动后打开浏览器 |

生产网页位于 `apps/web/dist`，需单独托管并将 `/api`（包括 SSE）代理到后端，保留下游插件 WebSocket 连接。控制台面向本机使用，尚未提供完整公网登录和权限管理。

```text
apps/web/         Vue 3 + TypeScript 控制台
apps/server/      Node.js 后端：账号、路由、下游、集成、API
apps/dsh-plugin/  dsh 连接插件
apps/extension/   SillyTavern 扩展
packages/         共享消息处理与协议实现
```

配置、会话和历史保存在 `apps/server` 本地运行文件中，表情与适配任务等保存在 `data/`；已排除出 Git，请自行备份。配置采用原子写入，旧配置会按版本迁移。详见 [后端架构](apps/server/ARCHITECTURE.md)。
