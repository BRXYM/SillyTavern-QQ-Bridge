# SnowLuma Bridge

**多 QQ、多下游的自由控制台。**

统一管理多个 QQ 账号，将下游连接和会话配置组合成轻量消息流程，再为不同会话选择流程。面向喜欢折腾 AI 和聊天机器人的个人玩家，支持本地部署。

```text
多个 QQ 账号 → OneBot v11 → 会话选择流程
                              ↓
              上游处理 → 调用下游 → 下游处理 → 原账号回复
             （会话配置） （连接） （会话配置）
```

## 核心概念

| 对象 | 负责什么 | 示例 |
|---|---|---|
| QQ 账号 | 消息从哪里进入、用哪个账号回复 | 主号、测试号 |
| 下游连接 | 地址、协议、认证和服务状态 | 本机 dsh、酒馆、自建 HTTP 接口 |
| 会话配置 | 如何处理对话内容 | 前置提示词、输入前后缀、输入与回复处理规则 |
| 消息流程 | 组合连接、配置与处理开关 | dsh 日常聊天、HTTP 客服 |
| 会话管理 | 为会话选择流程、管理会话变量 | 私聊选日常聊天，群内某成员选客服 |

同类型下游可以创建多个实例。下游只管理连接、认证和协议字段映射；会话配置独立保存，可供多个流程复用。流程负责组合，会话管理只选择流程。

会话可继承全局默认流程，也可单独选择流程。当前尚未提供账号级默认流程。群聊按「账号 + 群 + 成员」隔离，同一群内不同成员可以独立绑定。

## 已有能力与边界

- **多 QQ**：多条 OneBot v11 连接，按账号隔离会话，从收到消息的原账号回复。支持 SnowLuma，也可手动接入其他兼容 OneBot v11 的协议端。
- **多下游**：dsh 插件 / headless、SillyTavern、同步 HTTP GET/POST。HTTP 支持 JSON / 纯文本响应、请求模板、响应字段提取及环境变量凭据引用。
- **会话配置**：只编辑前置提示词、输入前后缀、发送前处理与回复后处理。提供纯文本预览，不调用下游；支持替换、删除、去除标记内容。
- **消息流程**：固定四步工作台，组合已有连接和会话配置，可分别跳过上游或下游处理。提供模拟执行、真实调用测试和逐步骤记录。
- **会话管理**：维护默认流程、每个会话的流程绑定与变量；支持按账号、流程和关键词筛选。
- **回复处理**：统一触发与准入规则、文本处理、回复分段、发送节奏、图片表情。
- **运行状态**：账号与下游状态、日志、SSE 状态推送及错误提示。
- **上游连接**：读取 SnowLuma 已有的 OneBot 端点后主动连接，也可手动填写地址和 token。明确区分账号记录、注入状态与 OneBot 连接状态。

HTTP 目前支持同步 GET/POST 与 JSON / 文本响应，不支持 SSE、异步轮询和任意脚本。上下文由具体下游维护，HTTP 会话标识和前置提示词需要通过协议模板映射到目标接口支持的字段。下游页保留折叠的 AI 辅助连接入口，使用 dsh 生成连接参数与协议映射；保存时不创建会话配置。

## 快速开始

需要 Node.js >= 22、pnpm >= 11、一个 QQ OneBot v11 协议端和一个可用下游。

```bash
git clone https://github.com/BRXYM/SillyTavern-QQ-Bridge.git
cd SillyTavern-QQ-Bridge
git checkout next
pnpm install
```

`next` 是完整前后端工程；`main` 保留历史版本。首次运行（PowerShell）：

```powershell
Copy-Item apps/server/config.example.json apps/server/config.json
pnpm dev
```

打开 <http://localhost:5178>：

1. 在 **上游连接** 中检测 SnowLuma，选择已读取的 QQ，点击「连接此 QQ」。QQ 须先在 SnowLuma 中手动注入，并启用 OneBot WebSocket 服务。控制台只读取已有端点，不修改 SnowLuma 文件；也可手动添加 OneBot 连接。
2. 在 **下游连接** 中添加或启用服务，填写地址、认证与协议映射。默认使用 dsh，也可连接酒馆或 HTTP 服务。
3. 在 **会话配置** 中创建前置提示词、输入内容和消息处理规则，使用示例文本预览效果。
4. 在 **消息流程** 中新建流程，选择连接与会话配置；点击步骤卡片设置是否启用两侧处理。先用模拟回复预览，再按需真实调用测试。
5. 保存并设为默认流程，或在 **会话管理** 中为已有会话单独选择流程。
6. 在 **消息流程 → 最近执行** 查看步骤输入、输出、耗时与错误。账号状态与运行日志位于对应页面；消息触发开关位于 **系统设置**。

注入诊断优先读取 SnowLuma 的进程接口；Windows 可补充检查 QQ 主进程与 SnowLuma 注入管道。无法读取、需要 WebUI 登录或无法对应账号时，显示“未知”，不会把连接失败直接当作“未注入”。控制台不执行自动注入，也不修改自动注入开关。

### dsh

需要时安装 `npm install -g @deepseek-ai/dsh`。在下游连接中展开 dsh 实例，探测安装位置、设置 profile，并使用「一键安装插件」。源码位于 `apps/dsh-plugin`。详细操作见 [后端说明](apps/server/README.md)。

### SillyTavern

把 `apps/extension/` 复制到酒馆的 `public/scripts/extensions/third-party/SnowLuma-Bridge/`，重启酒馆，确认扩展连接 Bridge 的 WebSocket 端口（默认 9500），再启用酒馆下游。

### 自建 HTTP 服务

在下游连接中新增 HTTP 类型，配置 URL、method、headers、timeoutMs、response 和 requestBody。requestBody 属于接口协议映射，例如：

```json
{
  "message": "{{input.text}}",
  "system": "{{input.system}}",
  "session_id": "{{input.sessionKey}}"
}
```

前置提示词与文本处理在会话配置中定义；认证使用请求头中的 `{{env.变量名}}` 引用。不要将真实密钥提交到仓库。

### 旧配置兼容

旧版下游的命名配置会以稳定 ID 导入独立会话配置，只提取对话字段。旧绑定显示为「兼容流程」，继续采用原处理方式，无需手工修改 sessions.json。编辑保存兼容流程时，需选择会话配置或关闭处理步骤；此后采用新流程定义，连接未改变时保留旧协议覆盖。酒馆使用新前置提示词时需更新仓库内的连接扩展。

## 轻量消息流程

流程固定为 **上游处理 → 调用下游 → 下游处理 → 回复 QQ**。两侧处理共用一份会话配置，分别执行其中对应区域；关闭上游处理会跳过提示词、提取与输入规则，关闭下游处理会跳过回复提取与规则。两侧均关闭时直接透传文本。

- **模拟执行**：使用填写的模拟回复，不访问下游、不发送 QQ、不写真实变量；可沿用模拟状态连续预览多轮。
- **真实调用测试**：调用已保存流程的下游，使用独立测试会话，结束后请求清理；不发送 QQ、不修改真实会话变量。外部服务可能产生正常调用费用或自身记录。
- **QQ 消息执行**：经过原触发与准入检查后执行所选流程，从原账号回复。下游或持久化失败会停止后续步骤；QQ 投递失败会记录，不自动重试。

最近执行仅保留当前进程最近 50 次，重启清空。可展开查看四步状态、输入输出、前置提示词、耗时和变量变化；单段正文记录最多 4096 字，不采集连接请求头或认证配置。消息正文与提示词本身仍可能包含用户填写的敏感内容。

首版采用固定顺序，支持 HTTP、dsh 和酒馆等现有适配器。分支、循环、并行、多下游串联、任意代码节点和分布式调度尚未实现。

## 双向消息处理与单会话变量

会话配置分为两个区域：**上游消息处理（QQ → 下游）**决定发给服务的消息和前置提示词；**下游消息处理（下游 → QQ）**决定返回 QQ 的回复。两侧的开头 / 结尾追加分别作用于各自方向，不会混用。

每侧依次执行：从原始消息或模板来源提取数据 → 更新会话变量 → 文本处理 → 前后追加。上游阶段还会展开前置提示词。支持正则捕获组和 JSON 点路径提取，例如 `data.name`、`items.0.name`。

| 引用 | 含义与生效阶段 |
|---|---|
| `{{message.upstream}}` | 本轮 QQ 原文，两侧都可用 |
| `{{message.downstream}}` | 本轮服务原始回复，仅下游阶段可用 |
| `{{current.upstream.nickname}}` | 本轮上游提取的 nickname |
| `{{current.downstream.ticket}}` | 本轮下游提取的 ticket，仅下游阶段可用 |
| `{{previous.upstream.nickname}}` | 上一次成功处理的上游提取值 |
| `{{previous.downstream.ticket}}` | 上一次成功处理的下游提取值 |
| `{{vars.nickname}}` | 当前会话的持久变量 |

这些引用可用在提取来源、赋值内容、前置提示词、两侧前后追加内容，以及替换规则的替换文本中。用户消息中的同名字符串不会被递归解释。其他软件已有的宏（例如 `{{char}}`）保留原文。

例如：上游用 `我叫(.+)` 提取 `nickname`（捕获组 1），将 `{{current.upstream.nickname}}` 赋给变量 `nickname`，提示词写 `请称呼用户为 {{vars.nickname}}`。下游从 JSON 的 `data.ticket` 提取 `ticket`；下一轮上游提示词可引用 `{{previous.downstream.ticket}}`。上游阶段不能引用尚未产生的本轮下游回复，配置校验会提示改用上一轮数据。

提取未匹配时，本轮提取值为空并产生诊断；变量赋值默认不以空结果覆盖旧值，也可取消该开关以主动清空。同一阶段的所有提取先完成，变量赋值随后同时生效；同阶段赋值之间不能依赖行顺序。

变量按完整会话标识隔离（账号 + 私聊对象，或账号 + 群 + 成员），切换配置时同名变量沿用。初始值只在变量不存在时使用。变量和上一轮提取值保存在 `apps/server/data/conversation-state.json`，重启保留，已排除出 Git；应与其他运行数据一起备份。文件损坏时停止加载并报错，不会静默清空。

同一会话的消息顺序执行；不同会话各自处理。只有启用会话配置且下游调用成功后，才原子保存本轮变量和提取历史；失败时全部丢弃。成功调用后即保存，QQ 投递失败不会撤销下游已产生的结果。停用会话配置期间不更新提取历史。

会话管理中的「变量」可查看和编辑某个会话的变量，并查看上一轮提取结果。如果编辑期间新消息更新了变量，保存会被拒绝，须重新读取。当前限制为每会话 32 个变量、每值 4000 字，避免无界增长。

配置页可连续预览多轮，上一轮预览结果作为下一轮的模拟状态。预览不调用下游、不保存真实变量，随时可以重置。

## 开发与部署

```bash
pnpm dev          # 前后端
pnpm dev:web      # 仅前端
pnpm dev:api      # 仅后端
pnpm build        # 构建前端
pnpm start        # 仅后端，不托管网页
pnpm test         # 自动化测试
pnpm typecheck    # 前后端类型检查
```

| 环境变量 | 默认值 | 用途 |
|---|---|---|
| WEB_PORT | 5178 | 开发控制台 |
| API_PORT | 9510 | HTTP API |
| EXT_PORT | 9500 | 下游插件 WebSocket |
| ONEBOT_URL / ONEBOT_TOKEN | 配置文件 | 覆盖第一个 QQ 账号连接 |
| ST_DATA_DIR | 自动探测 | 酒馆数据目录 |
| BRIDGE_OPEN | 关闭 | 设为 1，启动后打开浏览器 |

生产网页位于 `apps/web/dist`，需单独托管并将 `/api`（包括 SSE）代理到后端，保留下游插件 WebSocket 连接。控制台面向本机使用，尚未提供完整公网登录和权限管理。

```text
apps/web/         Vue 3 + TypeScript 控制台
apps/server/      Node.js 后端：账号、路由、下游、集成、API
apps/dsh-plugin/  dsh 连接插件
apps/extension/   SillyTavern 扩展
packages/         共享消息处理与协议实现
```

配置、会话和历史保存在 `apps/server` 本地运行文件中，表情与适配任务等保存在 `data/`；已排除出 Git，请自行备份。配置采用原子写入，旧配置会按版本迁移。详见 [后端架构](apps/server/ARCHITECTURE.md)。
